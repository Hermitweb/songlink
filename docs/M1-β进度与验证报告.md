## 5b. 本轮产品化增量（组合根 + 音频串流）

**组合根配置化**：`Host.Core` 的 `run` 入口由 `HostConfig`（`appsettings.json` + 命令行 `--port/--adapter/--assembly/--type/--pin`）驱动；`AdapterFactory` 内置 `fake`，外部适配器（如 `smtc`）通过**反射按配置加载程序集**——Host.Core 不硬依赖 WinRT 工程，故本机可编译/测试，开发机切真 SMTC 只改配置不动代码；未知适配器且未给 assembly → 清晰报错退出。

**音频串流并入 Host**：新建 `SongLink.Host.AudioStream`——`AudioStreamSink`（UDP 收→`AudioFrame` 解析→Concentus 解 Opus→`IAudioRenderer`）；`WasapiRenderer`（真机→PC 默认输出/蓝牙）与 `NullRenderer`（无设备可测）可注入；`HostServer` 在 `audio:start/stop` 起停 sink，`setSourceMode(PC_LOCAL)` 自动停 sink 交还输出；`AudioFrame`（§4）提升到 `SongLink.Protocol` 跨栈共享。

**验证与边界**：以上均本机编译 0 错、由 47 项测试覆盖（含 UDP→Concentus→NullRenderer 解码回路 0 丢帧）；真实 WASAPI 出声需声卡、手机侧 `AudioPlaybackCapture` 抓取需 Android 10+ 真机（源码见 `spike/audio-stream/android`、`remote`）。

## 6. 过程中发现并修复的真实缺陷（诚实记录）

这些多在"同机自测"下被掩盖，靠更严格的测试/联调才暴露，值得沉淀：

1. **同机自测掩盖跨栈/局域网 bug**：#1、#2 只有在"异机 + 异栈客户端"才暴露——用同机 .NET 客户端跑 selftest 全绿，但手机根本连不上、Kotlin 帧会被丢。对策：加异栈 schema 校验 + 双进程联调用例。
2. **鉴权信息泄露**：#6 的鉴权门最初只挡"入站指令"，没挡"出站广播"，未鉴权连接仍收到 state。集成测试抓出后修复（广播只发已鉴权）。
3. **ClientWebSocket 取消即废**：selftest 用"取消 ReceiveAsync"做超时会把 socket 置 `Aborted` 不可恢复，导致后续块崩溃。改为后台 reader 灌 Channel、只取消 Channel 读。
4. **`--no-build` 用旧二进制**：改共享库（Protocol）后没重建引用方，集成测试假失败。对策：改库后重建全部引用方。
5. **Concentus 参数语义**：`Encode/Decode` 第 2 参是每声道帧长（960）非总样本，传错越界——音频 spike 调试中修正。
