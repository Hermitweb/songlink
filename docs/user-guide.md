# SongLink User Guide 用户指南

## 产品简介

**SongLink（点歌台）** 是一套面向家庭/聚会 KTV 场景的点歌系统：

- **Windows Host（电脑端）：** 播放中心，操控音乐 App，并通过 Web 面板提供点歌、队列、歌词、历史
- **Android Remote（手机端）：** 扫码/手动配对连接、点歌台（点歌 / 队列 / 歌词副屏）、音频串流、历史导出

> **当前能力边界（2026-10-19 核对）**
>
> - 电脑端的 **Web 面板是功能完整的主界面**：点歌、队列、历史、歌词、音量、长辈模式都在这里。
>   面板的搜索/加入队列/歌词/封面已在真实浏览器里跑通（连内置适配器实测）。
> - **桌面 App 的音源**（状态栏右下角可随时切换，选择会被记住）：
>   - **本地音乐**（默认）：扫描 `%LOCALAPPDATA%\SongLink\library`，用系统默认设备真出声。
>     支持搜索点歌、播放/暂停/上下首、音量。**装完即用，不需要任何校准。**
>     第一次用请在面板里点「导入本地音乐」选一个放歌的文件夹。
>   - **接管正在播放**：通过 Windows 媒体会话控制电脑上**正在播放**的任意 App
>     （QQ音乐 / 网易云 / 酷狗 / Spotify…）的播放、暂停、上一首、下一首，并读取歌名歌手。
>     搜索会**聚合本地曲库 + 你启用的在线平台**，每条结果显示来源标记，
>     点歌时按来源送到对应入口，不会放错歌。
>
> **开启在线搜索/点歌（可选）**
>
> 1. 复制 [`docs/takeover.example.json`](./takeover.example.json) 到 `%LOCALAPPDATA%\SongLink\takeover.json`
> 2. 把 `acknowledgeRisk` 改成 `true`，并按需勾选 `platforms`
> 3. 重启点歌台，切到「接管正在播放」模式
>
> **面板上会看到每个平台的"真实能力"标签**（在「点歌」卡片里，搜索框下方）：
>
> | 标签 | 含义 |
> |---|---|
> | 🟢 **可点歌** | 搜得到，而且点下去客户端**真的在放**这首歌 |
> | 🟠 **只能搜** | 搜得到，但点不动（缺标定 / 客户端版本不支持），标签后面会写明原因 |
> | ⚪ **不可用** | 这个平台现在用不了 |
>
> 标签后面的文字是**最近一次点歌失败的具体原因**（如"没版权""要 VIP""坐标没标定"），
> 点歌失败或成功后会自动刷新。之所以要摆在明面上：有的平台只能搜不能点，
> 用户搜到歌就点、点了没响却不知道为什么，是最伤人的一种体验。
>
> **请先了解风险**：三家的在线搜索与点歌都依赖**非官方接口或客户端私有协议**，
> 随时可能失效（失效后点歌会如实报错，不影响其他功能），且涉及服务条款与账号风险。
>
> **关于搜索质量（实测）**：各平台的搜索只做关键词模糊匹配，**不区分原版与改编**，
> 还会混入无关热门歌。实测网易云搜「晴天 周杰伦」：
> 前 30 条里**全是**"深情版/女声版/钢琴版/DJ版"和"江南/十年/温柔"这类不相干的歌，
> 周杰伦原版要 `limit=100` 才出现，且排在**第 74 位**。
>
> 所以本产品对在线搜索做了两件事：**① 抓 100 条大窗口 → ② 本地重排（歌名/歌手精确匹配
> 加分，带"深情版/钢琴版/原唱/cover/remix"等标记的减分）→ ③ 排序后截断到 30 条**。
> 不做这层处理，用户点搜索结果第一条放出来的就是翻唱。
>
> | 平台 | 搜索 | 点歌方式 | 实测状态（2026-10-19 本机 Windows 验证） |
> |---|---|---|---|
> | **网易云(接管)** | ✅ 通 | **CDP 控制通道**（客户端带 `--remote-debugging-port=9223` 启动） | ✅ **实测完全可用**：点歌后当前曲目切到目标歌**并且真的起播**（`playingState == 2`）。需客户端带调试端口启动（点歌台可代为启动；客户端已在运行需先关闭） |
> | 网易云(深链接) | ✅ 通 | `orpheus://<base64>` | ❌ 协议已注册、下发无报错，但**不切歌**（静默失效）→ 已默认关闭 |
> | **QQ音乐** | ✅ 通（联想搜索，免登录） | **客户端界面点歌**（`clientUiPick`，见下） | ✅ **实测可用**：点歌后当前曲目切到目标歌**并且真的起播**。注意：非会员点 VIP 歌会弹付费窗（会如实报失败） |
> | **酷狗** | ✅ 通（免登录，~20ms） | 需你填 `playTemplate`，或做坐标标定 | ⚠️ 本机客户端 20.1.32 **不支持**社区那套 workbuddy 控制桥（需 ≥ 20.1.40），且未标定 → **只能搜、不能点** |
>
> **点歌成功 = 客户端真的在放这首歌**（不是"命令发出去了"）。实测三种失败都会被如实报出来：
> 切到了别的歌、没版权、要 VIP、客户端没响应 —— 面板上会显示具体原因，不再是一句"点歌失败"。
>
> **关于版权**：客户端能接受"当前曲目"的变更，但拿不到播放授权时状态会停在 `Stop`——
> 这在网易云上通常就是**这首歌没有版权**（实测周杰伦《晴天》在该账号下就是放不了）。
> 这时点歌会**如实报失败**并提示"可能没有版权"，而不是显示成功却一片安静。
>
> **关于 QQ音乐 的「客户端界面点歌」**：QQ音乐/酷狗的桌面客户端都是 CEF/自绘界面，
> 不向 Windows 暴露控件（UIA 读不到），也没有可用的注入通道
> （QQ音乐：无 CDP、7 种命令行参数实测全部无效、二进制里没有 `playbysongid`）。
> 所以点歌靠**驱动它自己的搜索框**：把窗口拉到前台 → 粘贴歌名 → 回车 → 点搜索结果，
> 再用**系统媒体会话**确认客户端确实切到了目标歌且在播。
> 坐标按 `descriptors/*.json` 标定（点歌前会把窗口调回标定尺寸），
> 并且会**逐行试点**直到媒体会话确认命中 —— 避免"赌一个固定坐标"点错歌。
>
> ⚠️ 这条路径会**接管你的屏幕**（抢焦点、往搜索框里打字、点结果），
> 所以在 `takeover.json` 里默认**关闭**，需要 `"clientUiPick": true` 显式开启。
>
> **为什么酷狗不预置播放模板**：调研时确认 `kugou://` 的播放 URL 格式仍无可确证的样例；
> 而社区那套在 Windows 上可行的方案（kugou-cli 的 `control start` 握手）需要客户端 **≥ 20.1.40**，
> 本机 20.1.32 的整个安装目录里字节级搜不到该协议（零命中），所以这条路在这台机器上走不通。
> 这反过来印证：靠猜一个 scheme 拼出来的链接，很可能只是"点了没反应"或放错歌。
> 所以默认留空，你在配置里填上自己验证过的模板才启用。
>
> **关于 QQ音乐搜索**：实测 `client_search_cp` 端点已失效（HTTP 500）、
> `u.y.qq.com/cgi-bin/musicu.fcg` 无登录态返回 `code 500003`、网页版搜索页是纯前端渲染抓不到数据。
> 现改用 `c.y.qq.com/splcloud/fcgi-bin/smartbox_new.fcg`（联想搜索，免登录，实测可用），
> 再用 `fcg_play_single_song.fcg?songmid=…` 补时长/专辑/会员标记。
> 代价是它给的是**联想结果**（通常几条到几十条），不如完整搜索全 —— 这是免登录条件下的取舍。
>
> - 手机端已实现：**扫码/手动配对连接**、**点歌台三页（搜索点歌 / 队列操作 / 滚动歌词副屏）**、
>   音频串流、播放历史导出。
> - 手机端点歌台与电脑 Web 面板**共用同一套队列**，两边操作会实时互相反映。
> - **两端都会记住这台点歌台**：首次输入一次 PIN（网页扫码同理）后，
>   配对凭据会存在本地，之后**重新打开面板 / 重开 App 都不再要求输 PIN**。
>   点歌台每次开机 Host 的 PIN 都会变，所以记住的是 Host 签发的长期 token；
>   token 失效时（Host 重启）会自动退回 PIN，并在网页上提示"点歌台已重启，请重新输入一次 PIN"。
>   手机端若连不上（比如换了 WiFi 导致地址变了），在配对页改地址即可。
> - **进度条跳转（seek）两端都未实现**：Host 协议没有 `seek` 指令，
>   适配器接口 `IPlayerAdapter` 也没有 Seek 方法（QQ音乐/酷狗等自绘界面无法可靠定位）。
>   因此两端进度条**只做展示、不可点击**。
> - **手机 → 电脑 串流**（把手机正在播放的歌送到电脑音箱，并把手机的歌名/歌词/封面显示到电脑面板）
>   代码链路已打通，但**没有任何真机验证**。
> - 以上能力**均未经过真机验证**，仅有编译与单元测试覆盖。
>   详见 [`真机测试最终报告.md`](../真机测试最终报告.md)。

## 快速开始

### 第 1 步：安装并启动点歌台

**普通用户走安装包路径：**

1. 双击运行安装包 `dist\SongLink_Setup_v1.0.0.exe`
2. 安装向导默认装到 `%LOCALAPPDATA%\SongLink`，属于当前用户目录，**不需要管理员权限**
3. 安装完成后启动「SongLink 点歌台」（桌面快捷方式或开始菜单）
4. 启动后自动打开 Web 面板，页面顶部显示本机地址和 PIN

记下页面显示的 **PIN 码**，手机端配对时要用。

> 产物说明：
> - `dist\SongLink_Setup_v1.0.0.exe` — 交付给用户的安装包（Inno Setup）
> - `dist\SongLink-win-x64\SongLink.exe` — 未打包的发布目录产物，是 WinForms 桌面壳（非 Host CLI），仅供开发/排障直接运行
> - 仓库中**不存在** `publish\win-x64\SongLink.Host.exe`，早期文档中的该启动路径已作废

### 命令行方式（仅开发/调试用）

```powershell
# 开发调试：直接运行发布目录里的桌面壳
.\dist\SongLink-win-x64\SongLink.exe

# 从源码运行 Host（仅开发用）
# 注意：localsource 是**外部适配器**，必须同时给出程序集与类型全名，只写 --adapter 会报
#       "未知适配器 'localsource'"。内置可直接 --adapter=fake。
dotnet run --project src\SongLink.Host.Core -- `
  --adapter localsource `
  --assembly src\SongLink.Host.Adapters.LocalSource\bin\Debug\net8.0-windows\SongLink.Host.Adapters.LocalSource.dll `
  --type SongLink.Host.Adapters.LocalSource.LocalSourceAdapter
```

> 上面的程序集路径需要先构建一次 LocalSource 项目：
> `dotnet build src\SongLink.Host.Adapters.LocalSource\SongLink.Host.Adapters.LocalSource.csproj`

Host 启动后控制台会输出类似：

```
[host] 监听 ws://0.0.0.0:51999/ PIN=123456
适配器=localsource caps=ReadMeta,Transport,Pick,Search
```

### 第 2 步：连接手机端

#### 方案 A：Web 面板（手机浏览器，最快上手）

Web 面板的「热门」卡片底部有「手机连」按钮，点击可生成配对二维码。用**手机上的点歌台 App** 选择

> 注意：二维码内容是 `{"wsUrl":...,"pin":...}` JSON，由 App 内的扫码器解析。
> **用手机浏览器直接扫这个码只会显示一段 JSON 文本，不会连上点歌台**，请务必用 App 扫码。

现役遥控端源码在 `mobile/android-remote`，应用包名 `songlink.remote`。

# 产物：mobile\android-remote\app\build\outputs\apk\debug\app-debug.apk

2. 安装到手机：`adb install -r app\build\outputs\apk\debug\app-debug.apk`
3. 打开 App，在配对页按面板显示填写连接信息与 PIN

连接成功后应能看到鉴权成功与 Host 握手信息。

## 功能详解

### 1. 点歌模式（Pick Page）

支持的音源类型与**真实可用状态**：

| 类型 | 描述 | 当前状态 |
|------|------|---------|
| **LocalSource** | 本地音乐文件夹 | 开箱可用，无需任何配置。**唯一零校准的路径** |
| **QQMusic** | QQ 音乐（坐标驱动 + 系统媒体会话校验） | ✅ **实测可用**（需在 `takeover.json` 里开 `clientUiPick`）。descriptor 已按 1226x800 标定；点歌前会把窗口调回该尺寸，并逐行试点直到媒体会话确认命中 |
| **NeteaseMusic** | 网易云音乐（CDP 控制通道） | ✅ **实测可用**（走 `netease-cdp`，需客户端带调试端口启动） |
| **KugouMusic** | 酷狗音乐 | ⚠️ **只能搜、不能点**。客户端 20.1.32 不支持社区的 workbuddy 控制桥（需 ≥ 20.1.40），且未做坐标标定 → 坐标字段为 `null`，点歌会如实报"未标定" |

说明：

- 第三方 App 适配器（QQ音乐 / 网易云 / 酷狗）均为 CEF / 自绘界面，未向 Windows UIA 暴露控件，
  因此**不能靠 UIA 点歌**。QQ音乐 走的是**坐标驱动 + 系统媒体会话校验**（见上）；
  坐标是**窗口内归一化坐标**，并配了标定窗口尺寸（点歌前会调回该尺寸），
  换显示器/缩放不影响；换客户端版本导致布局变了才需要重新标定。
- 旧版 OCR 兜底的 `searchBoxPoint` / `resultRegion` 仍是**屏幕物理像素坐标**，
  与分辨率、缩放比、窗口位置强绑定，换显示器或改缩放比例后必须重新校准。
- 校准过程必须在装了对应 App 的**交互式桌面**上手动完成，无头环境与 CI 覆盖不到。
- 排查与校准细节见 `docs/M2-点歌校准手册.md` 中的逐 App 校准状态表。

#### 操作流程
```
手机输入关键词 → Host 返回搜索结果 → 点击选择 →
Host 调用对应 Adapter.Pick(title, artist) →
PC 音乐 App 开始播放
```

---

### 2. 队列管理（Queue Management）

支持的操作：

- **添加：** `queue.add` → 加入新曲目到队尾
- **置顶：** `queue.top {index}` → 将指定曲目移至队首
- **删除：** `queue.remove {index}` → 移除指定位置
- **清空：** `queue.clear` → 清空所有排队曲目

队列状态更新：
每次操作后，手机端会收到 `EventFrame{name: queue-updated}` 并自动刷新列表

---

### 3. 歌词副屏（Lyrics Page）

功能特性：

- **自动同步**：基于 SMTC position 驱动时间轴
- **LRC 加载**：优先本地文件，其次联网拉取（LRCLib）
- **偏移校准**：支持 ±500ms 手动微调
- **滚动显示**：选中歌词行高亮

校准方法：

1. 播放一首歌曲
2. 如果歌词延迟，拖动 Slider 增加 offset（如 300ms）
3. Host 会立即重发带新 offsetMs 的 Lyric 帧
4. 手机端歌词随之对齐

---

### 4. 音源模式切换（Source Mode）

**PC_LOCAL（默认）**
- PC 上的音乐 App 或本地音源出声
- 歌词封面从 PC 推送给手机

**PHONE_STREAM（手机音频串流）**
- 手机音频经网络串流进 PC
- PC 再用自身蓝牙/音箱输出
- 元数据由手机端上报

切换方法（调用方协议）：
```javascript
await remote.cmd("setSourceMode", {"mode": "PHONE_STREAM"})
// 或
await remote.cmd("setSourceMode", {"mode": "PC_LOCAL"})
```

## 本地音源使用（LocalSourceAdapter）

本地音源是目前唯一不需要任何校准、开箱即用的点歌来源。

### 准备阶段

1. 准备一个存放音乐的文件夹，路径由你自己决定，例如：

```
D:\我的音乐
```

   建议放在本地磁盘（不含 OneDrive 同步占位文件），子目录也会被递归扫描。

2. 放入 MP3 / WAV / FLAC 格式的音乐文件
3. 建议命名规范：`歌手 - 歌名.mp3`（例如 `周杰伦 - 晴天.mp3`），元数据更容易匹配

### 导入本地音乐

推荐做法是通过 Web 面板操作：

1. 打开 Web 面板（桌面端启动后自动打开，手机浏览器可扫码访问）
2. 点击「导入本地音乐」，选择你准备好的音乐文件夹
3. 导入完成后，曲库会出现在搜索与点歌列表中

也可以直接把文件复制进已导入的文件夹，Host 会在下次扫描时收录。

### 验证效果

在手机端：

1. 选择「本地音源」来源
2. 搜索任意歌名，应能看到自己的曲库
3. 点击播放，PC 端开始出声

## 网络与连接

### 局域网发现（mDNS）

```bash
# 查看可用主机
ping songlink-host.local
```

### 蓝牙配对（RFCOMM）

如果 Wi-Fi 不可用，可以：

1. PC 开启蓝牙广播：`--adapter=bluetooth`
2. 手机端搜索并配对（输入 PIN）
3. 建立 RFCOMM 连接传输指令
4. **限制：** 仅支持文本数据（无歌词/封面），仅作为备用手段

## 常见问题解决

### Q1：搜索结果为空？

**原因：** 本地音源库为空，或第三方 App 适配器未校准。

**解决：**
- 先确认已在 Web 面板导入本地音乐文件夹（最简单可靠）
- 若要接 QQ音乐/网易云/酷狗，需按 `docs/M2-点歌校准手册.md` 完成校准，并确认对应 App 正在运行
- 确认 descriptors 中 OCR 坐标已按当前分辨率校准

---

### Q2：点歌失败？

**原因：** UIA 读不到控件，OCR 兜底也未命中。

**排查步骤：**
1. 确认目标 App 窗口位置与 descriptor 中的坐标假设一致（OCR 坐标与分辨率强绑定）
2. 检查控制台日志是否有 OCR 识别结果
3. 重新测量并调整 descriptors 中的 `searchBoxPoint` / `resultRegion`

---

### Q3：歌词不对齐？

**原因：** SMTC position 存在延迟误差。

**解决方法：**
1. 手机端长按歌词行，弹出校准 Slider
2. 拖动到准确位置
3. Host 立即下发新 lyric 帧生效

---

### Q4：手机连不上 Host？

**可能原因：**
- 端口 51999 被防火墙拦截
- Host 只绑定 localhost（而非 0.0.0.0）
- 手机与 PC 不在同一网段

**解决：**
```powershell
# 检查端口占用
netstat -ano | findstr :51999

# 放行防火墙规则（需管理员权限）
netsh firewall add portopening TCP 51999 "SongLink" ENABLE
```

## 安全建议

1. **设置固定 PIN**（不要每次随机生成）：
   ```powershell
   dotnet run --project src/SongLink.Host.Core -- --pin="123456"
   ```

2. **启用帧签名模式**（防止同网伪造指令）：
   ```json
   { "RequireFrameSig": true }
   ```

3. **仅允许局域网访问**，不要把 51999 端口暴露到公网

## 高级用法

### 双人点歌接力

两台手机同时连接 Host，可轮流点歌，队列按 FIFO 处理。

### 歌词主题自定义

修改歌词样式文件，或向手机端渲染层替换自定义字体。

### 批量导入专辑

直接把你选定的音乐文件夹整个拷入已导入的目录，或在 Web 面板重新导入该文件夹即可。

## 性能调优建议

1. **StateGate 节流频率**：可下调以降低 CPU 占用（默认 1Hz 通常已足够）
2. **ReplayBuffer 容量**：按内存大小调整（默认 128 条）
3. **OCR 兜底开关**：若某 App 的纯 UIA 路径可用，可关闭 OCR 以减少负载
