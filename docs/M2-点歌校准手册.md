# M2 点歌适配器校准手册（UiaProbe 驱动）

目标：为一个具体音乐 App（QQ音乐/网易云/酷狗…）产出可用的 `AppDescriptor`，让 `UiaPickAdapter` 能"点任意歌"。这是架构里唯一的 🔴 高风险模块，成败取决于该 App 的 UIA 暴露程度，**必须在装了该 App 的交互式 Windows 桌面**上校准。

> 本仓库开发用的 bash 会话是非交互窗口站，`UiaProbe list` 会返回 0 窗口——请在**你自己登录的桌面**上运行本手册步骤。

## 先读这一段：使用门槛与风险提示

本手册是**面向开发者/高级用户**的操作文档，不是普通用户的安装指引。接入第三方音乐 App 必须付出以下成本：

1. **手写 descriptors JSON**：仓库内所有 descriptor 均为空模板或占位值，没有任何 App 提供了开箱可用的完整配置。你需要自己判断走 UIA 路径还是 OCR 路径，并手写对应字段。
2. **按自己的显示器分辨率校准 OCR 像素坐标**：`searchBoxPoint` / `resultRegion` 是屏幕物理像素，与分辨率、缩放比例、窗口位置强绑定。仓库中现有的 `kugou.json` 坐标只是**占位值**，注释已写明「需按实际分辨率校准」。换显示器、改缩放、挪窗口都必须重校。
3. **必须在交互式桌面手动操作**：这些 App 为 CEF/自绘，不向 Windows UIA 暴露控件，只能靠 OCR 兜底；OCR 依赖 `MediaOcrEngine`（WinRT）。无头环境、后台会话与 CI **覆盖不到**这一步，无法自动验证。

**风险提示：** 对非技术用户而言，以上三步基本不可完成，实际很可能卡在中间状态——App 能搜到但点不中，或坐标点歪。

**LocalSource（本地音乐文件夹）是唯一低门槛路径**：把音乐放进自选文件夹、在 Web 面板点「导入本地音乐」即可使用，不需要写 JSON、不需要校准坐标、不需要交互式桌面调试。**普通用户请直接走这条路径。**

## 前置
1. 开发机装带「Windows 应用程序开发」工作负载的 VS / Windows App SDK（使 SMTC/OCR 适配器可编译）。
2. `dotnet build src/SongLink.Host.Adapters.UiaPick src/SongLink.Host.Adapters.Ocr src/SongLink.Tools.UiaProbe`
3. 目标 App 已安装并能正常运行。

## 步骤 A：UIA 路径（App 暴露控件时优先）
1. 启动目标 App（如 QQ音乐）。
2. `UiaProbe list` → 找到它的窗口（记下标题/进程名）。
3. `UiaProbe dump <进程名或标题> 6` → 在树里找：
   - **搜索框**：`ControlType.Edit`，记录其 `AutoId=`（→ `searchBoxAutomationId`）或 `Name=`（→ `searchBoxName`）。
   - **结果项**：点歌后搜索结果的 `ControlType.ListItem`/首条，记录 `AutoId=`（→ `resultItemAutomationId`）或 `Name` 正则。
4. 填 `src/SongLink.Host.Adapters.UiaPick/descriptors/<app>.json`：
   ```json
   { "appId":"qqmusic", "exeNames":["QQMusic"], "searchBoxAutomationId":"...",
     "resultItemAutomationId":"...", "doubleClickResult":true, "pickTimeoutMs":6000 }
   ```
5. 运行 Host 并点歌验证：
   ```bash
   dotnet run --project src/SongLink.Host.Core -- run --adapter uia \
     --assembly SongLink.Host.Adapters.UiaPick.dll \
     --type SongLink.Host.Adapters.UiaPick.UiaPickAdapter \
     --inner smtc --descriptor src/SongLink.Host.Adapters.UiaPick/descriptors/<app>.json
   # 另开：dotnet run --project src/SongLink.RemoteSim -- --url ws://localhost:51999/ --pin <PIN> --cmds "pick:晴天:周杰伦"
   ```
   成功：QQ音乐搜索框被填入、回车、首条结果被双击播放。失败（`pick` 返回 false）→ 走步骤 B。

## 步骤 B：OCR 兜底路径（CEF/自绘、UIA 读不到控件时）
1. `UiaProbe dump <app> 2` 若几乎读不到 Edit/ListItem，即属此类（架构 R2）。
2. 确定两个坐标（可用截图量取或 `UiaProbe` 输出的 `Rect=`）：
   - **搜索框中心** → `searchBoxPoint:[x,y]`（OCR 路径点它聚焦再键入歌名）。
   - **结果区域** → `resultRegion:[x,y,w,h]`（OCR 只在该区找歌名并点击）。
3. descriptor 加 `"ocrLanguageTag":"zh-Hans"`；Host 运行时带 `--ocr-assembly SongLink.Host.Adapters.Ocr.dll`（注入 `MediaOcrEngine`）。
4. 同步骤 A 第 5 步点歌验证；`UiaPickAdapter` 先试 UIA、失败自动走"点搜索框→键入→回车→截图→OCR→匹配歌名→点中心"。

## 验证与回归
- 每个 App 校准后，把 descriptor 提交进 `descriptors/`，并在 `spike/smtc-probe` 的 `dump` 能力矩阵里确认该 App 的 SMTC 读/控也 OK（点歌依赖 inner=smtc 的读/传输）。
- 若某 App 两条路都不稳，降级为"仅传输控制 + 本地音源（import）"——产品仍可用（架构 §11 务实结论）。

## 已知
- 本手册的"运行/枚举/点歌"步骤需交互式桌面 + 目标 App，属真机验证项，未在本仓库 CI/无头环境覆盖。
- 工具本身（UiaProbe、UiaPickAdapter、MediaOcrEngine）已编译通过；纯逻辑（OcrPickStrategy、descriptor 解析、工厂装配）有 71 项测试覆盖。
